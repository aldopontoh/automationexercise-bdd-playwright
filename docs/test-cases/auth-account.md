# ISTQB Test Case Matrix: Authentication & Account Lifecycle (`auth-account`)

**PRD Source**: [docs/prd/auth-account.md](../prd/auth-account.md)  
**Design Techniques Applied**: Equivalence Partitioning (EP), Boundary Value Analysis (BVA), State Transition Testing (STT), Error Guessing (EG).

| Test ID | Requirement ID | Priority | Test Type | Design Technique | Preconditions | Test Steps | Test Data | Expected Result |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **TC-AUTH-01** | `REQ-AUTH-01` | P0 (`@smoke`, `@e2e`) | Positive / State Transition | State Transition Testing | Guest user, dynamic unique user data | 1. Navigate to `/login`, fill `New User Signup!` and click `Signup`.<br>2. Complete `/signup` Account & Address form and click `Create Account`.<br>3. Verify `Account Created!` and click `Continue`.<br>4. Verify `Logged in as <name>` in header.<br>5. Click `Delete Account`, verify `Account Deleted!`, click `Continue`. | Dynamic `testDataFactory.createUser()` | Full lifecycle transitions cleanly: `/login` → `/signup` → `/account_created` → `/` (`Logged in as`) → `/delete_account` (`Account Deleted!`), leaving zero orphaned accounts. |
| **TC-AUTH-02** | `REQ-AUTH-02` | P1 (`@regression`) | Negative | Equivalence Partitioning & Error Guessing | Guest user on `/login` | 1. Verify error banner and URL. | Email: `invalid.qa.9999@example.com`, Password: `WrongPassword!123` | Page stays on `/login`; `"Your email or password is incorrect!"` is displayed. |
| **TC-AUTH-03** | `REQ-AUTH-03` | P1 (`@regression`) | Negative / Duplicate Check | Error Guessing | Ephemeral user created and logged out (auto-cleaned in `After` hook) | 1. Register an ephemeral user and log out.<br>2. On `/login`, submit `New User Signup!` using the exact same email.<br>3. Verify duplicate email error. | Existing ephemeral user email | Registration is blocked on `/signup` (or `/login`) and `"Email Address already exist!"` is visible. |
| **TC-AUTH-04** | `REQ-AUTH-04` | P0 (`@smoke`, `@e2e`) | Positive / State Transition | State Transition Testing | Ephemeral user registered (auto-cleaned in `After` hook) | 1. Click `Logout` in header.<br>2. Verify redirection to `/login`.<br>3. Log back in with the ephemeral user's email and password.<br>4. Verify header status. | Ephemeral user credentials | Logout redirects to `/login`; re-login restores `Logged in as <name>` in the header. |
| **TC-AUTH-05** | `REQ-AUTH-05` | P2 (`@regression`) | Negative / Input Validation | Boundary Value Analysis | Guest user on `/login` | 1. Enter malformed email `"bad-email"` in Login email field and click `Login`.<br>2. Verify HTML5 `checkValidity() === false`.<br>3. Leave Signup name/email empty and click `Signup`.<br>4. Verify HTML5 `checkValidity() === false`. | Malformed: `"bad-email"`, Empty: `""` | Both Login and Signup forms fail native HTML5 validation and do not navigate away from `/login`. |
