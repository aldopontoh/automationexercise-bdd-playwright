# PRD: Authentication & Account Lifecycle (`auth-account`)

## 1. Module Overview, Business Objective & Risk Priority
- **Module Slug**: `auth-account`
- **Business Objective**: Provide secure account registration, login, session persistence, logout, duplicate-email enforcement, input validation, and self-service permanent account deletion.
- **Risk Priority**: **Critical** (P0 gate for all authenticated workflows and live-site self-cleaning safety).

## 2. Entry Points, Routes & Preconditions
- **Routes**: `/login`, `/signup`, `/account_created`, `/logout`, `/delete_account`.
- **Preconditions**: Registration and login flows start in Guest state with unique ephemeral credentials generated by `utils/testDataFactory.js`. All created accounts MUST be deleted via `/delete_account` (either explicitly in the test or via the `After` hook).

## 3. Atomic Functional Requirements
- **REQ-AUTH-01**: Completing `New User Signup!` on `/login`, filling all mandatory Account & Address Information fields on `/signup`, and clicking `Create Account` MUST transition to `/account_created` (`Account Created!`), authenticate the user (`Logged in as <name>` in header), and allow permanent deletion via `Delete Account` (`/delete_account` → `Account Deleted!`).
- **REQ-AUTH-02**: Submitting non-existent or mismatched credentials in `Login to your account` on `/login` MUST remain on `/login`, keep the user unauthenticated, and display `"Your email or password is incorrect!"`.
- **REQ-AUTH-03**: Submitting an already registered email address in `New User Signup!` (`POST /signup`) MUST keep the user on the Login/Signup view (`/signup` or `/login`), block progression to the Account Information form, and display `"Email Address already exist!"`.
- **REQ-AUTH-04**: Clicking `Logout` (`/logout`) while authenticated MUST clear the session, redirect to `/login`, and allow the user to re-authenticate cleanly with their registered email and password (`Logged in as <name>`).
- **REQ-AUTH-05**: Attempting to submit empty or malformed email/password fields in either the Login or Signup forms on `/login` MUST be rejected by native HTML5 constraint validation (`required` and `type="email"`).

## 5. Validation Rules, Boundary Conditions, Ad/Modal Handling & Negative Scenarios
- On `/signup`, `#email` is pre-populated and `disabled: true`.
- On `/signup`, `#zipcode` lacks an associated `<label for="zipcode">` in the live DOM; therefore `#zipcode` / `[data-qa="zipcode"]` is the verified resilient selector.
- On duplicate signup submission, Django renders the Login/Signup template directly on the `POST /signup` response URL (`/signup`) with `"Email Address already exist!"`.
- On `/delete_account`, the live page `<title>` remains `Automation Exercise - Account Created` (known AUT defect); assertions check the visible `Account Deleted!` heading and confirmation copy.

## 6. Testable Acceptance Criteria
- **Given** a guest completes new user registration with unique test data, **Then** `Account Created!` displays, the header shows `Logged in as <name>`, and clicking `Delete Account` displays `Account Deleted!` (`REQ-AUTH-01`).
- **Given** a guest submits invalid credentials on `/login`, **Then** `"Your email or password is incorrect!"` is displayed (`REQ-AUTH-02`).
- **Given** an ephemeral user already exists, **When** a guest tries to sign up with that same email, **Then** `"Email Address already exist!"` is displayed on `/signup` (or `/login`) (`REQ-AUTH-03`).
- **Given** an authenticated ephemeral user logs out, **When** they log back in with their credentials, **Then** `Logged in as <name>` is visible again (`REQ-AUTH-04`).
- **Given** a guest leaves required fields empty or enters a malformed email on `/login`, **Then** HTML5 native validation reports invalid state and blocks submission (`REQ-AUTH-05`).
