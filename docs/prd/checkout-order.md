# PRD: Checkout & Order Confirmation (`checkout-order`)

## 1. Module Overview, Business Objective & Risk Priority
- **Module Slug**: `checkout-order`
- **Business Objective**: Ensure authenticated shoppers (whether registering before checkout, registering during checkout, or logging in before checkout) can verify their delivery and billing addresses, inspect order line items and grand total, submit an optional delivery comment, validate payment fields, confirm synthetic sandbox orders, and download their purchase invoice cleanly.
- **Risk Priority**: **Critical** (revenue conversion, customer address accuracy, and invoice generation).

## 2. Entry Points, Routes & Preconditions
- **Routes**: `/view_cart`, `/checkout`, `/payment`, `/payment_done/<amount>`, `/download_invoice/<amount>`.
- **Preconditions**: All checkout scenarios use ephemeral test accounts generated by `utils/testDataFactory.js` and cleaned up automatically via `/delete_account`.

## 3. Atomic Functional Requirements
- **REQ-CHK-01**: Navigating to `/checkout` as an authenticated user with an item in cart MUST display `Address Details` with both `Your delivery address` (`#address_delivery`) and `Your billing address` (`#address_invoice`) matching the user's registration profile (name, street, city/state/zip, country, mobile), plus `Review Your Order` with the expected line item and total (`Rs. 500` for `Blue Top`) (`AE-TC-23`).
- **REQ-CHK-02**: Entering an order comment in `#ordermsg textarea[name="message"]` and clicking `Place Order` (`/payment`) MUST transition cleanly to `/payment` displaying heading `Payment` and all required payment inputs (`name_on_card`, `card_number`, `cvc`, `expiry_month`, `expiry_year`, and `Pay and Confirm Order`).
- **REQ-CHK-03**: Registering before checkout and submitting synthetic dummy card details on the practice `/payment` form MUST navigate to `/payment_done/<amount>` and display `"Order Placed!"` and `"Congratulations! Your order has been confirmed!"` (`AE-TC-15`).
- **REQ-CHK-04**: Attempting to click `Pay and Confirm Order` on `/payment` with missing required card fields MUST be blocked by native HTML5 constraint validation (`required` on all 5 payment fields) and remain on `/payment`.
- **REQ-CHK-05**: `/checkout` and `/payment` MUST expose valid SEO `<title>` tags (`Automation Exercise - Checkout`, `Automation Exercise - Payment`), clear semantic headings (`Address Details`, `Review Your Order`, `Payment`), and accessible action controls (`Place Order`, `Pay and Confirm Order`).
- **REQ-CHK-06**: Adding a product as a Guest, clicking `Proceed To Checkout` → `Register / Login` inside `#checkoutModal`, completing registration, returning to `/view_cart`, proceeding to `/checkout`, entering an order comment, and confirming synthetic sandbox payment MUST display `"Order Placed!"` and allow clean account deletion (`AE-TC-14`).
- **REQ-CHK-07**: Logging in with a pre-registered ephemeral user before checkout, adding a product to cart, reviewing checkout details, submitting synthetic sandbox payment, and confirming MUST display `"Order Placed!"` and allow clean account deletion (`AE-TC-16`).
- **REQ-CHK-08**: Clicking `Download Invoice` on `/payment_done/<amount>` MUST trigger a valid file download (`invoice.txt`) containing non-empty invoice text, followed by a working `Continue` link (`AE-TC-24`).

## 5. Validation Rules, Boundary Conditions, Ad/Modal Handling & Negative Scenarios
- All 5 payment fields carry `required: true` in the live DOM.
- Live-Site Safety: Only synthetic dummy test strings (`QA Sandbox Card`, `0000000000000000`, `123`, `12`, `2030`) are allowed on this practice sandbox.
- Invoice download verification captures Playwright's native `download` event in Playwright's temporary download folder so no untracked files are written into the Git working tree.

## 6. Testable Acceptance Criteria
- **Given** an authenticated user with `Blue Top` in cart visits `/checkout`, **Then** delivery and billing addresses match registration data and the order total is `Rs. 500` (`REQ-CHK-01`).
- **Given** the user adds an order note and clicks `Place Order`, **Then** `/payment` loads with all 5 payment fields visible (`REQ-CHK-02`).
- **Given** a newly registered user adds an item and submits synthetic dummy payment details, **Then** `"Order Placed!"` and `"Congratulations! Your order has been confirmed!"` are displayed (`REQ-CHK-03`).
- **Given** the user leaves payment fields empty and clicks `Pay and Confirm Order`, **Then** HTML5 validation blocks submission and URL stays on `/payment` (`REQ-CHK-04`).
- **Given** an authenticated user navigates across `/checkout` and `/payment`, **Then** page titles, semantic headings, and accessible action buttons are properly exposed (`REQ-CHK-05`).
- **Given** a guest adds a product, registers from the checkout modal, and confirms payment, **Then** `"Order Placed!"` is displayed (`REQ-CHK-06`).
- **Given** an existing ephemeral user logs in before checkout, adds a product, and confirms payment, **Then** `"Order Placed!"` is displayed (`REQ-CHK-07`).
- **Given** an authenticated user completes an order, **When** they click `Download Invoice`, **Then** a non-empty `invoice.txt` file downloads cleanly (`REQ-CHK-08`).
